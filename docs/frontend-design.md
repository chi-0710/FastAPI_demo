# Flowspace 前端设计规范

> 版本：1.4 · 更新日期：2026-11-22
>
> 适用范围：当前工作台、Agent 实验室，以及后续新增的业务页面。
> 本文记录现有设计的意图、实现基线和扩展规则。后续修改前先阅读本文；改变公共视觉规则时同步更新本文。

## 1. 设计定位

**一个安静、清晰、有轻微生命感的个人工作空间。**

用户进入页面后，应先理解当前可以做什么，再感受到细节带来的舒适。任务清单是主要工作区域，Agent 是可以逐步探索的辅助能力。

风格关键词：**浅色、灰绿、留白、柔和边界、克制立体感、轻量动效**。

| 原则 | 落地方式 |
| --- | --- |
| 清晰 | 页面有明确主标题和主要操作；业务内容与辅助说明分层 |
| 安静 | 大面积使用近白背景；绿色集中在主操作、选中状态和重点装饰 |
| 轻盈 | 用细边框和背景色区分卡片；常规面板减少阴影 |
| 有温度 | 中文文案简短自然，反馈具体；避免生硬的管理后台口吻 |
| 有秩序 | 相同操作复用相同组件；空间、字号和颜色保持语义一致 |
| 真实 | 数据、连接状态、Agent 模式都来自实际行为，装饰不伪装成业务状态 |

新增功能应延续这套语言。霓虹渐变、大面积黑色、强烈玻璃效果、满屏发光、夸张弹跳不属于当前风格。

## 2. 页面结构与视觉重心

### 2.1 工作台

页面按“定位 → 行动 → 查看进展 → 实际操作”组织：

1. 左侧导航：品牌、工作空间、功能入口、文档和账号管理。
2. 顶部栏：面包屑、真实服务状态、刷新；窄屏补充账号入口。
3. 标题区：日期、页面主标题、说明，以及「新建任务」主要操作。
4. 主题区：专注主题文案与绿色悬浮勾选装饰，建立品牌记忆。
5. 统计区：三张轻量卡片，展示本页任务、已完成数量与完成率。
6. 业务区：左侧任务清单占据主要宽度；右侧 Agent 入口和小提示辅助引导。
7. 页脚：轻量品牌收尾，避免引入额外操作负担。

主题区只用于概览页。后续增加任务详情、设置或运行记录时，优先给实际业务留空间，不必每页复制主题大卡片。

### 2.2 Agent 实验室

主内容是对话与输入框，桌面右侧提供简短使用建议。消息区有独立滚动范围；用户消息靠右，Agent 消息靠左，错误结果有单独的浅红底色。

始终能看出当前执行器是否启用、是否为模拟模式。未来接入真实模型后，沿用当前视觉框架，扩展模型选择、工具调用和任务状态；不要把开发日志直接铺进普通对话流。

以下是当前源码中的实际基线。新增页面优先复用这些语义，不随意增加相近色。

| 辅助说明 | `#6d7b70` | 页面介绍、卡片说明、对话框说明 |

统计图标使用三组轻柔辅助色：

| 类别 | 底色 | 图标色 |
| --- | --- | --- |
| 任务／薄荷绿 | `#eef5ed` | `#638965` |

主题区采用低对比绿色渐变：`#eff4e9 → #f3f6ef → #e9efdf`，叠加轻量径向光晕。它是主题装饰的特例，常规表单和业务卡片保持纯色。

`--muted: #7a8781` 是已有基础变量；实际说明文字已通过后续规则调整为更深的颜色。修改时不要只改 `--muted` 就假定所有辅助文字都会变化。

## 4. 字体与信息层级

字体栈：

```css
font-family: Inter, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

目前没有加载远程字体或内置字体文件；Inter 只在设备已安装时使用，否则按顺序回退。不同操作系统的字形存在合理差异，布局不能依赖某一字体的精确字宽。

根字号为 `16px`，组件主要使用 `rem`。

| 层级 | 当前主要基线 | 使用原则 |
| --- | --- | --- |
| 页面主标题 | `1.9rem`，字重 600 | 每个视图一个主标题；手机约 `1.45rem` |
| 主题区标题 | 桌面 `1.9rem`，字重 500 | 行高 1.55，保持轻松的两行节奏 |
| 面板标题 | `1rem`，字重 600 | 明确划分任务、对话等功能区 |
| 任务标题／消息正文 | `1rem` | 核心业务内容优先保证可读性 |
| 常规按钮／筛选 | 通常 `0.875rem` | 通过字重和底色突出，避免全部加粗 |
| 说明文字 | 通常 `0.875rem` | 行高约 1.7～1.9 |
| 日期／分页等元数据 | 通常 `0.75rem` | 作为补充信息，不承担主要操作说明 |
| 英文眉题／品牌注脚 | 约 `0.6875rem`～`0.75rem` | 使用字距制造节奏，只承载辅助信息 |

部分已有组件和手机断点因更高优先级规则使用更小字号，以上不是所有元素的计算样式保证。**后续新增内容以正文 16px、操作标签 14px、元数据 12px 为优先基线**，优先换行、隐藏装饰或调整布局，不延续小字号例外。

英文大写仅用于简短眉题和模式标签；操作按钮、错误说明和主要业务内容使用中文。中文标题不要大范围增加字距，避免手机上的不自然断行。

## 5. 布局、间距与形状

### 5.1 当前桌面尺寸

| 项目 | 基线 |
| --- | --- |
| 左侧导航宽度 | `232px` |
| 顶栏高度 | `79px` |
| 主内容最大宽度 | `1600px`，位于侧栏右侧区域 |
| 主内容内边距 | 顶部 `35px`，左右 `42px` |
| 统计卡片间距 | `18px` |
| 主业务区列间距 | `22px` |
| 右侧辅助栏宽度 | `270px` |
| 面板内部留白 | 通常 `20px`～`25px` |
| 任务行最小高度 | `77px` |

扩展时优先从 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40` 的间距序列选择。已有 `18 / 22 / 25 / 42px` 是当前构图的具体值；不需要为了统一数字而机械修改全部布局。

### 5.2 圆角与边界

| 组件 | 当前圆角 |
| --- | --- |
| 标签 | `5px` |
| 筛选项 | `6px` |
| 小图标按钮／导航项 | `9px` |
| 常规按钮 | `10px` |
| 消息气泡／提示卡片 | `12px` |
| 统计卡片 | `13px` |
| 业务面板 | `16px` |
| 主题区 | `18px` |
| 对话框 | `22px` |

圆角随组件尺度增大；不要所有元素都做成胶囊。当前 `--radius` 为 `18px`，但并未统一驱动所有组件。

普通卡片主要依靠 1px 边框分层。阴影集中在主按钮、浮动提示和模态框；主题勾选块的内阴影用于塑造柔和立体感，是唯一明显的立体装饰。

## 6. 组件约定

| 组件 | 必须保持的行为与样式 |
| --- | --- |
| 主按钮 `.button.primary` | 深绿色白字；标识当前区域最重要的操作 |
| 次按钮 `.secondary` | 浅灰绿底；用于取消、断开等辅助操作 |
| 危险按钮 `.danger` | 红色；仅用于明确破坏性操作，配确认说明 |
| 图标按钮 `.icon-button` | 线性图标、轻量 hover 底色；必须有可访问名称 |
| 导航 `.nav-link` | 当前页用浅绿底和深绿文字，设置 `aria-current` |
| 筛选 `.filter` | 分段背景；选中项白底轻阴影，用 `aria-pressed` 表达状态 |
| 任务行 `.task-row` | 左侧完成控件，中间标题和元数据，右侧编辑与删除 |
| 已完成任务 | 勾选、文字弱化、删除线共同表达；仍可编辑或恢复未完成 |
| 空状态 `.empty` | 小图标、简短标题、具体说明，可提供一个下一步操作 |
| 对话框 `dialog` | 聚焦单一动作；标题、说明、输入、错误、底部按钮顺序稳定 |
| Toast | 底部居中短反馈；失败用文字说明；不能替代必须持续可见的表单错误 |
| Agent 消息 | 使用 `textContent` 渲染内容；当前不将模型输出当作 HTML |

常规按钮目标高度为 44px。现有行内、分页与手机控件有更小尺寸，后续触摸体验优化应扩大点击区域，而不是仅放大图标；目前不声称所有控件均达到 44px。

状态至少考虑：默认、悬停、键盘聚焦、处理中、禁用、成功、失败。新组件不能只设计正常数据已经加载完成时的样子。

## 7. 动效规范

### 学习提示轮播卡片

侧栏 `.learning-carousel` 展示五条学习提示，按 **5 秒**间隔循环。标题和说明以 **350ms 的淡入淡出与 5px 位移**切换；所有提示共享同一个网格位置，卡片高度由最长内容决定，切换时不推动侧栏其他元素。

底部五条短线是实际按钮，仅当前项高亮；点击立即切换并重新计时。可通过 Tab 聚焦，Enter / Space 选择。鼠标悬停或键盘焦点位于卡片内部时暂停，二者均离开后从完整 5 秒重新开始；点击后焦点仍在卡片内，因此不会马上自动切走。

卡片不提供「暂停／播放」按钮或手动播放开关，保留悬停与焦点暂停。页面进入后台、卡片在 ≤960px 的布局中隐藏时停止计时；恢复可见后重新计时。

启用系统“减少动态效果”时停止自动播放和过渡动画，仅保留短线手动切换。自动切换不触发读屏播报，手动选择才播报文案；非当前项使用 `aria-hidden` 和 `inert` 隐藏语义。

文案集中在 `frontend/assets/learning-tips.js` 的 `learningTips` 数组，增删时按钮数量自动同步；调度位于 `tip-rotation.js`，间隔默认值为 `5000`；视觉样式集中在 `learning-tips.css`。新增提示保持短标题与两行简短说明，避免卡片因长文案变高。

动效有三个目的：解释变化、反馈操作、提供少量环境感。业务操作应立即响应，不能为了等待动画而延迟网络请求。

| 动效 | 当前实现 | 设计意图 |
| --- | --- | --- |
| 页面区块入场 `enter` | 650ms，透明度 0→1，Y 轴 15px→0 | 轻轻进入，建立阅读顺序 |
| 区块错峰 | 主题 70ms、统计 140ms、业务区 210ms | 避免所有元素同时出现的生硬感 |
| 任务行入场 | 300ms，每行错开 25ms | 让列表加载可感知 |
| 主按钮 hover | 200ms，上移 2px，阴影小幅加深 | 明确可点击，不改变布局 |
| 勾选反馈 `pop` | 300ms，缩放 0.75→1.12→1 | 轻微完成感 |
| 主题勾选块 `float` | 7s 循环，上浮约 12px，轻微旋转 | 慢速环境动效，仅用于装饰 |
| 浮动标签 `drift` | 6s 循环，上浮约 9px | 与主题装饰形成轻微错位 |
| 刷新图标 `spin` | 1s 线性循环，请求结束停止 | 告知刷新进行中 |
| 骨架 `shimmer` | 1.5s 循环，浅色渐变移动 | 为真实加载等待提供反馈 |
| 进度条 | 宽度过渡 700ms | 使比例变化易于察觉 |
| 对话框 | 220ms `ease-out` 入场 | 快速而柔和地聚焦当前操作 |
| Toast | 250ms，淡入并上移 20px；通常约 4.5s 后收起 | 低干扰地反馈结果 |

现有 `enter`、`pop` 等未显式声明时序函数时使用 CSS 默认 `ease`，不是弹簧动画。切换视图或重新渲染可能再次触发入场；若后续频繁刷新，应避免无意义地反复播放。

保留 `prefers-reduced-motion: reduce` 分支：关闭动画和过渡，并取消平滑滚动。装饰元素不参与可访问内容，主题插画区域保持 `aria-hidden="true"`。

不要加入持续闪烁、快速抖动、打断输入的滚动动画，或与真实执行状态无关的“假进度”。大范围动画优先使用 `transform` 与 `opacity`。

## 8. 图标与插画

图标集中在 `icons.js`：SVG `viewBox="0 0 24 24"`，一般尺寸 20px，描边 1.7，圆角线帽与连接，颜色使用 `currentColor`。

新增图标沿用这套线性风格。不要混合实心彩色图标、Emoji 和线性图标作为同级导航。小星形等装饰符号可保留在非功能区域。

主题插画通过 CSS 渐变、圆角、阴影、透视轨道和 SVG 勾选构成，不依赖外部图片。半透明与模糊只在小面积浮动标签和对话框遮罩使用，不扩散到所有业务面板。

后续若新增图片，先确认它是否帮助理解或建立品牌；无实际作用时保留留白。

## 9. 响应式规则

断点按视口宽度工作。`max-width` 规则会累积生效，并受后文覆盖影响。

| 断点 | 当前布局变化 |
| --- | --- |
| ≥1500px | 主区顶部留白增大；主题区至少 310px；右侧栏 300px |
| ≤1200px | 侧栏 205px；主内容左右 26px；辅助栏 235px；工具栏允许换行 |
| ≤960px | 侧栏变为 78px 图标栏；隐藏侧栏附属信息；顶栏出现账号按钮；Agent 视图单列 |
| ≤760px | 任务区改为单列；统计图标隐藏；顶部栏降为 65px；主题插画弱化 |
| ≤520px | 侧栏 60px；主内容左右 16px；筛选和搜索换行；辅助卡片单列；主题插画透明度降为 0.2 |

窄屏调整顺序：**隐藏装饰 → 重排辅助信息 → 允许文本换行 → 调整间距**。不要通过整体缩小页面或隐藏核心操作解决拥挤。

侧栏账号管理在窄屏隐藏后，顶部「账号与登录」必须仍然可用。导航缩成图标时，必须保留名称；不要只依赖鼠标悬停提示。

建议验收宽度：390、768、1024、1440px；额外查看断点两侧是否发生跳变或溢出。这是后续验收建议，不代表所有尺寸都已完成测试。

## 10. 文案与业务真实性

文案语气：温和、清楚、简短，直接说发生了什么以及下一步能做什么。

| 场景 | 延续的表达方向 |
| --- | --- |
| 主要操作 | 「新建任务」「保存修改」「登录工作空间」 |
| 空状态 | 「这里还没有任务，添加一个清晰的小目标吧。」 |
| 成功反馈 | 「修改已保存」「新目标已加入清单」 |
| 冲突 | 明确记录已更新，提示重新读取后再提交 |
| Agent 未配置 | 「当前未启用执行器」；不显示“AI 已就绪” |
| 模拟模式 | 明确标注模拟响应，不伪装成真实模型结果 |

业务真实性约束：

- 「本页任务」「本页完成率」只代表当前服务端分页返回的数据；不能改名为「全部任务」或「整体完成率」，除非后端提供对应统计。
- 搜索只过滤当前页，文案保留「搜索本页任务」。
- 服务状态来自真实健康检查；加载失败应展示失败或重试，不以空列表冒充成功。
- 密钥只在当前页面内存使用；不要为了减少操作而内置密钥或偷偷写入本地存储。
- 用户文本和模型结果不作为 HTML 拼接。未来加入 Markdown 渲染时需使用受控渲染与清理策略。

## 11. 源码映射与修改入口

前端通过 Vite 独立开发与构建，生产静态文件由独立 Nginx 或静态托管平台提供。API 地址在 `frontend/.env` 配置，后端只提供 API；拆分部署不改变本文视觉规范。

| 文件 | 职责 | 常见修改 |
| --- | --- | --- |

### CSS 维护注意事项

`styles.css` 首行导入 `layout.css`，随后再声明基础规则和可读性修正。最终样式取决于选择器优先级、加载顺序和媒体查询，不能把某个文件里的第一条声明当作最终结果。

典型例子：通用 `[data-icon]` 设置显示方式，窄屏统计图标通过更具体的 `.stat .stat-icon` 隐藏。改变通用图标样式时，应复查窄屏隐藏行为。

当前样式文件仍有压缩为长行的规则和分散的颜色值。后续做样式重构时，可格式化并逐步提取语义变量，但必须保留视觉回归基线，避免持续在文件末尾堆叠高优先级补丁。

建议后续新增的变量命名为 `--color-surface`、`--color-text-secondary`、`--space-*`、`--radius-*`、`--motion-*`。这些是维护方向，当前并未全部实现；不要直接假定它们已经可用。

## 12. 新页面与修改验收

新页面沿用 `.shell`、`.topbar`、`main` 和 `.page-heading`，再根据任务选择 `.panel`、列表或表单。先复用现有组件，确实存在新语义时再增加变体。

每次修改按以下顺序检查：

1. 确定影响范围：是一个组件，还是公共颜色、字号、间距或布局规则。
2. 查找已有样式与状态，优先在正确层级修改，避免重复实现。
3. 检查正常、空、加载、失败、禁用以及长文本状态。
4. 检查桌面和窄屏，确保没有横向溢出、标题遮挡、核心操作丢失。
5. 检查键盘聚焦、可访问名称、减少动态效果设置；增加新配色时检查文字与底色的对比度。
6. 验证真实接口流程；涉及公共规则时同时检查工作台、Agent 页和对话框。
7. 更新本文相关数值或行为说明，并在变更记录中写明原因。

当前已存在焦点样式、跳转主内容链接、原生模态对话框、部分状态播报及减少动态效果分支；这些不等同于已完成完整无障碍审计。不要把现有小字号、低对比或紧凑点击区域直接复制为新组件标准。

可供后续设计任务复用的说明：

> 延续 Flowspace 的浅色灰绿工作空间风格：近白背景、白色业务卡片、深绿主操作、细边框、适度圆角、充分留白。任务和信息层级优先，线性图标统一，装饰仅在主题区域使用。动效轻量、短促且尊重减少动态效果设置。复用现有组件，保留真实加载与错误状态，检查桌面和手机布局，并同步更新 `docs/frontend-design.md`。
